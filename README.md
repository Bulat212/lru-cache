# LRU Cache

Типобезопасная, потокобезопасная реализация LRU (Least Recently Used) кэша на Go с использованием generics.

## Возможности

- Универсальность по типам ключей и значений через дженерики (Go 1.18+)
- O(1) для операций `Set` и `Get`
- Потокобезопасность (`sync.Mutex`)
- Без внешних зависимостей — только стандартная библиотека

## API

| Метод | Описание |
|---|---|
| `NewCache[K, V](capacity int) *Cache[K, V]` | Создаёт новый кэш заданной ёмкости |
| `(c *Cache[K, V]) Set(key K, value V)` | Добавляет или обновляет значение по ключу |
| `(c *Cache[K, V]) Get(key K) (V, bool)` | Возвращает значение по ключу и флаг, найдено ли оно |
| `(c *Cache[K, V]) Clear()` | Удаляет все элементы из кэша |

## Как это работает

Кэш построен на связке:
- **`map[K]*list.Element`** — быстрый доступ к узлу по ключу за O(1)
- **`container/list`** (двусвязный список) — порядок использования: голова списка — самый свежий элемент, хвост — самый давно неиспользуемый

При каждом обращении (`Get`) или обновлении существующего ключа (`Set`) элемент перемещается в начало списка. Когда кэш переполнен, из хвоста списка вытесняется элемент, а соответствующая запись удаляется из map.

## Тесты

​```bash
go test -v -race -cover
​```

Тесты покрывают:
- базовую логику `Set`/`Get`/`Clear`
- вытеснение по переполнению ёмкости
- LRU-специфичное поведение — что "освежённый" через `Get` элемент не вытесняется раньше более старых, но неиспользуемых элементов
- потокобезопасность под конкурентной нагрузкой (`go test -race`)

## Ограничения

- Тип ключа должен удовлетворять `comparable` (требование Go для использования в качестве ключа map)
